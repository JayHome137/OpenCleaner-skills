# 扫描性能基线

## 方法

运行 `python3 scripts/benchmark_scan.py`。脚本只使用临时目录，构造 24 个目录、每个目录 4 个 512 KiB 稀疏文件，总逻辑大小 48 MiB；同一子目录同时作为重复扫描目标，用于验证调度去重。

每种 worker 数执行 3 次，记录中位数、最小值、最大值和规范结果 SHA-256。该 fixture 用于发现性能或确定性回退，不代表真实主目录的绝对扫描耗时。

## 2026-08-22 本地基线

- 环境：macOS 26.5.2，arm64，系统 Python 3.9.6。
- 单 worker：中位数 `0.001572s`，范围 `0.001159s` 至 `0.002466s`。
- 4 workers：中位数 `0.001498s`，范围 `0.001481s` 至 `0.001541s`。
- 两种模式及两个独立进程的规范结果 SHA-256 均为 `9d1aa96d6e0173d82ae281fe412aa19bde0b2cc4f8948e5439341c9c8bd01e6d`。
- 请求根为 2 个，实际调度 24 个路径；重复的第 25 个路径没有再次调度。
- 报告项目为 24 个，无错误。

这个微型 fixture 中，并发调度开销高于扫描收益，因此 4 workers 并不更快。并发的价值主要出现在真实磁盘上的多个较大目录；代码仍把上限限制为 8，默认 4。验收关注结果稳定、重复目标不重复扫描、耗时没有数量级回退，而不是强制并发必须在微型 fixture 上更快。

## 回归方法

后续变更重新运行同一命令，并检查：

- `sequential.result_sha256` 与 `bounded_parallel.result_sha256` 相同。
- `scheduled_paths` 仍为 24。
- `reported_items` 仍为 24。
- 没有结构化错误。
- 中位数不存在数量级上升；若 fixture、Python 或系统版本变化，新增一条基线记录，不覆盖旧记录。
