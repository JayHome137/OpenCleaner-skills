> Mole 对照基线：官方 `main`，`ef2485a3a8f48c9abb11e4619635e476b1327566`
> 范围：本机最新版验证、已安装 Skill 对账、真实只读扫描、受控报告浏览器验收、Mole 官方源码静态审计。

## 结论

这部分已经跑完。P0/P1 的实现、单元与安全回归、macOS 临时 fixture、真实本机只读链路、静态与受控报告浏览器验收都已完成；此前文档里“待全量验证”和旧数量是文档没有收口，不是代码没有执行。

OpenCleaner 当前是一个可运行、可测试、默认失败关闭的 macOS 存储分析 Skill。它的产品重点已经明确为：准确解释空间占用，并以可恢复、可审计的方式释放空间。所有者工具管理的内容只显示归属、原因和建议命令，不生成删除动作；聊天摘要和完整 HTML 报告同时保留。

当前仍有三类真实边界，但都不是隐含缺陷：本机没有 Full Disk Access 导致扫描有权限遗漏；本轮没有对用户真实路径执行 Trash；Windows 公开入口继续关闭。Mole 的完整卸载、系统优化和实时硬件面板也不属于本 Skill 的目标。

## 真实本机只读结果

两次真实扫描的实时字段（时间、磁盘状态、错误文本和部分容量）会变化，但分类和策略数量稳定。由于扫描存在错误，缓存按设计保持 `published=false`、`status=scan_errors`，没有发布不完整结果。

### 扫描发现

| 分级 | 项数 | 估算容量 |
| --- | ---: | ---: |
| 绿灯：确定性规则候选 | 4 | `895,066,112 B`，约 `0.8 GiB` |
| 黄灯：需要解释或人工判断 | 95 | `84,621,533,184 B`，约 `78.8 GiB` |
| 红灯：只展示或保留 | 31 | `19,241,160,704 B`，约 `17.9 GiB` |

以上分级数字来自策略收紧前的历史只读扫描快照，仅用于说明当时发现了什么；不能代表当前代码会授予绿灯。当前 macOS 生产规则不向所有者工具管理的内容授予 Trash：Xcode `DerivedData`、Codex `.tmp`、普通缓存、npm、pnpm、Gradle、Go 和 Claude 都只提供说明。

### 当前决策

| 状态 | 项数 | 估算容量 | 说明 |
| --- | ---: | ---: | --- |
| 安全移入废纸篓（普通 `trash`） | 0 | `0 B` | 当前运行态或打开文件重验没有放行绿灯目标。 |
| 逐项人工复核（`reviewed_trash`） | 10 | `2,040,692,736 B`，约 `1.9 GiB` | 仅限受控的下载/临时直接子项或项目阶段生成目录，必须逐项确认。 |
| 只打开查看（`open`） | 105 | `94,358,310,912 B`，约 `87.9 GiB` | 只读定位，不授予删除权限；其中包括所有者工具和用户数据。 |
| 当前被阻止 | 25 | `10,399,449,088 B`，约 `9.7 GiB` | 见下方原因聚合。 |

被阻止原因：

- 打开路径超出允许范围：`21` 项，约 `8.9 GiB`；
- 目标或后代仍有打开文件：`2` 项，约 `0.7 GiB`；
- Codex 仍处于活动状态：`2` 项，约 `0.2 GiB`。

这些容量都是扫描估算，不等于已经释放的 APFS 空间。移入废纸篓后还需要用户自行决定是否清空废纸篓。

### 覆盖与 APFS 诊断

- 扫描覆盖：`可用于初筛`，完成 `96.0%` 的扫描根，记录 `22` 个权限拒绝和 `1` 个跳过根；报告提供授予 Full Disk Access 后重扫的建议，不自动修改系统权限。
- `purgeable`：本机本次读取不可用，报告明确标记为 unavailable，而不是猜测数值。
- 废纸篓估算：约 `32 MB`。
- 本地快照：`1` 个。
- 已删除但仍被进程打开的文件：两次扫描分别为 `138` 和 `136` 个，均约 `0.5 GB`。

报告只解释这些状态，不清空废纸篓、不删除快照，也不声称本次扫描已经释放空间。

## 与 Mole 核心代码的对照

Mole 是终端维护套件，不是单一存储 Skill。对照 clone 固定在 `ef2485a3a8f48c9abb11e4619635e476b1327566`，只做源码统计和阅读，没有运行 `clean`、`uninstall`、`optimize`、`purge` 或其他可能产生副作用的命令。该提交包含 `115` 个 `clean_*` 定义、`61` 个 Bats 测试文件、`1,701` 个 Bats `@test`、`325` 个 Go 测试函数。

| 核心面 | Mole | OpenCleaner 当前状态 | 判断 |
| --- | --- | --- | --- |
| 磁盘分析 | Go TUI、实时刷新、持久缓存、大文件排序过滤、多选 Trash | 一次性扫描 + stderr 进度 + 私有 TTL 缓存 + HTML/受控目录浏览 | 已吸收可复用的分析能力；仍没有 Mole 式常驻实时面板，这是范围选择。 |
| 已知缓存清理 | 大量 App/开发工具专用处理器 | owner-tool 内容统一只展示说明和命令；Downloads/临时直接子项与严格项目生成物走独立人工复核 | 覆盖面小于 Mole，但误删半径更小，符合已确认产品边界。 |
| 安全执行 | Dry Run、集中删除入口、路径保护；部分命令可永久删除或使用 sudo | Trash-only、action ID、一次性黄灯令牌、身份/父目录/运行态重验、批次先验 | OpenCleaner 更适合 Agent 场景，继续保持窄边界。 |
| 项目产物 | `purge` 覆盖广、可配置 | 独立项目阶段，要求 manifest、Git、checkpoint、idle、open-file gate | OpenCleaner 更严格，当前只提供受控复核入口。 |
| 安装包与 App | 安装器和完整卸载器 | DMG/PKG/ISO/XIP/ZIP 元数据视图、Bundle 归属、正规卸载说明 | 基础解释已具备，不把完整卸载器引入本 Skill。 |
| 操作历史 | `history` 支持文本和 JSON | 持久 JSONL + 最近跨会话摘要 | 核心能力已具备；长期趋势和导出仍可作为 1.2 体验增强。 |
| 系统维护与实时状态 | `optimize`、CPU/GPU/内存/网络健康面板 | 不支持 | 不属于“解释空间并安全释放”的目标，不建议加入。 |
| Agent 语义解释 | 不是核心能力 | 结构化 evidence/confidence 契约，实际内容由 Agent 补充 | 数据结构已固化，剩余工作是解释质量和证据完整性，而不是扩大删除权限。 |

## 仍有差距与 1.2 候选

这些项目不阻塞当前 1.1.0 本地验收，也不改变已确认的 Trash-only 边界：

1. **覆盖完整度。** 授予 Full Disk Access 后重新扫描，才能把“可用于初筛”提升为更完整的系统视图；Skill 只提供说明，不替用户改权限。
2. **Agent 解释质量。** 继续为陌生 UUID、容器和应用数据补充可复核的内容画像与最大子项，并对低置信度解释增加测试样例。
3. **历史趋势。** 当前已支持两次分析容量对比；长期导出和趋势图仍可作为后续体验增强。
4. **安装包判断。** 当前已补签名、镜像状态和唯一副本证据；更强的内容级判断仍保持黄灯人工复核。
5. **项目阶段表达。** 当前页面已显示阶段门状态和阻止原因；更完整的逐 gate 卡片仍可继续优化。

所有者工具命令已经按产品决策实现为“只展示”；`npm`、`pnpm`、`gradle`、`go`、Codex、Claude 和 Xcode `DerivedData` 都不生成删除动作。

## 明确不建议加入

- 完整 App 卸载器和残留清理器；
- DNS、Spotlight、LaunchServices、SQLite vacuum 等系统优化；
- CPU、GPU、内存、温度和网络实时监控；
- Touch ID、sudo 管理、软件自更新、Shell completion；
- 定时后台清理、常驻服务或自动清空废纸篓；
- 自动执行第三方包管理器或所有者工具的清理命令；
- 自动删除 Time Machine/APFS snapshot。

这些能力会扩大权限、测试矩阵和事故半径，却不会直接提高“解释磁盘并做出安全选择”的核心价值。

## 已确认的产品决策

1. **首要目标：准确解释并安全释放空间。** 释放必须可恢复、可审计；不以“尽可能多删除”为指标。
2. **所有者工具：只展示和说明。** 展示归属、为什么不能直接删、检查/清理建议命令，但不执行命令，也不提供删除入口。
3. **交付入口：两项都保留。** 对话提供简短决策摘要；HTML 是最终的只读证据和下钻入口；受控本地交互页面承接剩余的查看、复核和已授权操作。

## 验收边界与当前状态

- 本轮没有对用户真实文件执行 Trash，也没有启动真实用户路径的处置 session；文件操作内核由 `115` 项回归、macOS 临时 fixture 和受控服务测试验证。
- 受控服务页面已完成桌面与移动视口验收：黄灯按钮在确认勾选前保持禁用，所有者工具卡片没有删除入口，仅允许打开/查看，另可将路径加入保护列表；目录浏览明确声明只读。
- 静态 HTML 虽嵌入决策数据，但没有可执行的 session/action 控件，不能通过手工请求绕过服务端操作计划。
- Mole 只做官方源码审计，没有运行任何清理、卸载、优化或 purge 命令。
- 本轮验证临时产物仍保留在本机专用 `/tmp` 目录，按全局项目阶段规则等待静置条件后再做精确、可恢复的 Trash-only 清理；没有删除用户文件、废纸篓内容、快照或全局状态。
- 发布候选已在本地提交；推送后需以远端 CI 结果作为最终发布门槛。
